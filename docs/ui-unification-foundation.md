# UI統一基盤

この文書は、UI統一作業で採用する基準を記録する。

## 優先順位

1. 保存データ互換性を壊さない
2. 計算ロジックを変えない
3. 共通UIを先に揃える
4. 個別画面の例外を減らす
5. 最後にPC / モバイルの崩れを整える

## 共通化するもの

- 色
- 文字サイズと行間
- 枠線
- 角丸
- 影
- 余白
- 入力欄
- セレクト
- ボタン
- カード
- タブ / 選択状態
- 補足文 / 警告 / エラーの役割

## 色の原則

- 通常テキスト: 濃いニュートラル
- 補足: muted
- ブランド / 選択状態: 落ち着いた緑
- 赤: エラー / 削除 / 重大な矛盾に限定
- 黄・アンバー: 警告に限定
- グラフ系列やキャッシュフロー費目など、情報識別に必要な意味色は維持
- 通常の案内や未設定説明に赤を使わない

## 文字・レスポンシブの原則

- 本文15px、ラベル14px、補助13pxを基本とする
- スマホの主要入力欄は16px、主要操作は44px以上を基本とする
- ボタン文言、人物名、日付、件数、単位、短いラベルは意味の途中で不自然に改行しない

## CSSの責務

- `ui-system.css`: 配置・幅・共通部品の構造・レスポンシブ
- `ui-unification.css`: 色・面・枠線・選択状態・共通見た目
- `ui-typography-unification.css`: 文字サイズ・行間・可読性
- `ui-unification-screens.css`: Q1〜Q12の画面収束
- `ui-unification-shell-analysis.css`: ヘッダー・サイドバー・管理・分析画面
- `ui-text-integrity.css`: 不自然な改行の防止
- `mobile*.css`: 各画面固有のモバイル配置。共通見た目は持ち込まない

## index.cssの整理方針

`index.css` は長年の画面固有CSSを含むため、レイアウトまで一括削除しない。

後段の共通UIレイヤーで同一セレクタ・同一プロパティが確実に上書きされるものから、ビルド確認を挟みながら物理削除する。

2026-09-14時点で、以下の低リスク重複291件を削除済み。

- プラン管理: 11件
- シェル / ヘッダー / サイドバー: 46件
- 分析画面: 20件
- Q1〜Q12入力画面: 52件
- 旧文字サイズ・行間: 145件
- 共通UI部品: 17件

残る画面固有レイアウトは、PreviewでPC・スマホを目視してから必要箇所だけ整理する。

## 整理対象

- `tmp-*.json` 等の一時検証データ
- 使われていないCSS
- 旧デザイン専用の色指定
- 重複したスタイル定義
- 同一役割なのに画面ごとに異なるUI

保存データ項目・計算ロジック・migrationは、UI整理だけを理由に削除しない。

## 正式採用の条件

- Buildが成功すること
- Previewで主要画面を確認すること
- 保存データ・計算仕様へ変更がないこと
- ユーザーの明示承認後にのみmasterへ反映する
